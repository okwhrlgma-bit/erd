# 골든 작성 규칙

> 2026-08-16 하루에 **아홉 번** 걸린 것만 적는다. 이론이 아니라 그날 실제로 난 사고다.
> ★이 파일은 형제 repo(gambitry)에서 이식했다 — mutation 스윕 사례(체스 고유)는 뺀 본이다.
> ★이식 계기(2026-08-21): **이 규칙이 없던 앱에서** §11 의 사고가 그대로 다시 났다.
> 규칙이 3 repo 에만 있었고 앱은 6개였다 — **도구의 대상 목록이 대상과 공진화하지 않은** 그 클래스다.
> 앞선 규칙들이 "골든으로 잠가라"만 말하고 **어떻게 잠글지**를 말하지 않아 생긴 갭이다.

## 1. 형태가 아니라 성질을 잠근다 (그날 6회)

내가 만든 골든이 **개선을 여섯 번 막았다.** 전부 같은 모양이다 — 코드의 *문자열 형태*를 매칭했다.

```ts
// ❌ 그날 실제로 깨진 것들
expect(route).toMatch(/const c11 = \(\(acc\.match\(/);          // 판정식을 단일 소스로 모으자 RED
expect(src).toMatch(/const hidden = installed \|\| dismissed \|\| inApp \|\| \(!ios && !canInstall\);/);
```

두 경우 다 **개선이 맞았고 골든이 틀렸다.** 조건을 하나 더하거나 함수로 추출하면 빨개진다.

```ts
// ✅ 성질을 실행으로 확인한다
expect(countClauseChains(twoSentences)).toBeGreaterThanOrEqual(CLAUSE_CHAIN_LIMIT); // 단위가 답변 전체인가
for (const h of hiddenClauses) expect(h).toContain("inApp");                        // 조건이 물려 있는가
```

**판별 질문**: 이 검사는 *무엇이 참이어야 하는가*를 보는가, *어떻게 쓰였는가*를 보는가.
후자면 리팩터가 곧 RED다. 잠글 것은 계약이지 표기가 아니다.

### 1.1 특히 잘 걸리는 세 가지 (2026-08-30 · 하루에 셋 다 걸렸다)

유입 라벨에 도메인을 담으려고 정규식 하나를 넓혔더니 **골든 셋이 동시에 빨개졌다.**
제품이 옳게 넓어진 자리였고 셋 다 골든이 틀렸다.

| 박아 둔 것 | 무엇이 깨졌나 | 어떻게 고쳤나 |
|---|---|---|
| **허용 문자** `\[a-z0-9-\]` | 도메인의 점을 허용하자 RED | `\[[^\]]+\]` 로 열고, **형태 검사를 하기는 하는가**만 본다 |
| **함수 이름** `cleanId\(src\)` | 유입 라벨을 증강 id 검사에서 분리하자 RED | `clean[A-Za-z]*\(src\)` + "날것을 그대로 찍지 않는다"를 따로 검사 |
| **정규식 리터럴 위치** | 상수로 빼자(`const SRC_RE = ...`) 같은 줄만 보던 검사가 못 찾음 | 선언 줄도 함께 본다 |

★공통점: 셋 다 **제품이 나아진 방향으로 움직였을 때** 빨개졌다. 골든이 잡아야 할 것은
"클라이언트와 서버가 같은 검사를 쓰는가", "날것이 로그에 안 실리는가" 같은 **성질**이지
어떤 문자를 허용하는지나 함수 이름이 무엇인지가 아니다.

★반대로 **더 좁혀야 할 곳도 있었다**: 이름을 느슨하게 푸는 대신
`src=${src}` 처럼 날것을 그대로 찍는 형태는 **없어야 한다**는 검사를 새로 넣었다.
느슨하게만 풀면 관문을 통째로 지워도 통과한다.

## 2. 반증이 통과하면 그 골든은 아직 없는 것이다 (그날 3회)

새 골든은 **위반을 주입해 RED 를 확인**하고 복원한다. 그날 반증이 세 번 통과했다 — 전부 검사가 약해서다.

| 무엇을 잡으려 했나 | 왜 통과했나 | 어떻게 고쳤나 |
|---|---|---|
| 공용 로그 리더를 쓰는가 | `/readServerLog/` 가 **import 줄**에도 맞았다 | 호출을 본다 `readServerLog\s*\(` |
| 프로브 줄을 거르는가 | `/probe=1/` 이 **주석**에도 있었다 | 필터 코드를 본다 `\.filter\([\s\S]{0,40}probe` |
| 같은 필터 | `[^)]*` 가 화살표 함수의 `)` 를 못 넘었다 | 문자 클래스를 넓혔다 |

★**검사는 주석이 아니라 코드를 봐야 한다.** 그리고 **검사기가 검사 대상보다 약하면 안 된다** —
소스를 정규식으로 긁는 검사는 표기가 조금만 바뀌어도 깨지거나, 반대로 아무 데나 맞아 통과한다.
가능하면 **모듈을 import 해서 실행**하고, 소스를 읽어야만 한다면 무엇을 놓치는지 주석에 적는다.

### 2.1 ★개수로 성질을 대신하지 마라 (2026-08-30 · 반증에서 **넷 중 셋**이 통과했다)

새 앱의 데이터 정본 골든 여덟을 쓰고 반증했더니 **셋이 그대로 통과했다.** 원인이 하나다 —
세기 쉬운 것을 세고 성질을 봤다고 여겼다.

| 잠그려던 성질 | 내가 쓴 검사(개수) | 왜 뚫렸나 | 성질로 고친 것 |
|---|---|---|---|
| 두 기준선이 갈렸는가 | 각 묶음이 비어 있지 않은가 | **30일치를 72시간 가방으로 옮겨도** 둘 다 안 비어서 통과 | 30일치가 가방에 있으면 안 갈린 것이다 |
| 없는 수량을 지어냈는가 | 숫자 붙은 항목이 N개 이하인가 | **하나 더 지어내도** N 이하라 통과 | 어느 항목에 숫자가 붙는지를 정본대로 못박는다 |
| 상표를 넣었는가 | `[A-Z][a-z]+\d{2,}` 패턴 | **"Fenix PD36"** 이 그 패턴에 안 맞는다 | 품목이 전부 한글이라는 성질을 쓴다 |

★**판별 질문**: 내 검사가 세는 값이 **위반 뒤에도 그대로일 수 있는가.** 그렇다면 그건 성질이
아니라 곁다리다. 개수·존재·길이는 대개 곁다리다.

★통과한 하나는 겁주는 말 검사였는데, 그건 **금지 문자열을 직접 봤기** 때문이다.
성질을 직접 보는 검사는 반증을 견딘다.

## 3. 기준선을 우리가 만든 것으로 삼지 않는다 (그날 2회)

AI 티 검출기를 **우리가 쓴 정본 대사**로 교정하려 했다. 순환논증이다 — AI 가 쓴 것을 정상의 정의로
삼으면 검출기는 영원히 자기를 통과시킨다. 고쳐서 사람 글로 갈아탔는데 이번엔 **명령문**(PO 메시지)을
기준선으로 써서 8배라는 틀린 결론을 냈다. 말뭉치 언어학은 이걸 **데이터 편향**이라 부른다.

- 기준선은 **바깥에서**, 그리고 **장르를 맞춰서** 가져온다(대사는 대사와, 문어는 문어와).
- 실측 근거는 `scripts/corpus-clause-chain.py` 머리말(출처 링크 포함).

## 4. 레거시가 있으면 0 이라 말하지 말고 기준선으로 고정한다

`telemetry-readback-lint` 를 만들었더니 **46개**가 이미 안 읽히고 있었다. 전부 고칠 수 없다.

- 현재 상태를 `BASELINE_*` 로 박고 **새로 늘어나는 것만** 막는다.
- "0 건"이라 쓰지 않는다. 46개가 남아 있다는 사실을 목록으로 남기는 편이 정직하다.
- **기준선은 줄어들기만 하게** 별도 검사를 건다(해소했는데 목록에 남아 있으면 알려 준다).

## 5. 공허한 통과를 막는 첫 검사를 넣는다

코퍼스나 파일을 훑는 골든은 **빈 배열에도 통과**한다. 그래서 맨 앞에 이걸 둔다.

```ts
it("파일을 실제로 읽었다(공허한 통과 방지)", () => {
  expect(canonStrings().length).toBeGreaterThan(1500);
});
```

## 6. 오탐만 줄이고 변별력을 잃으면 검사가 아니다

검출기를 느슨하게 고칠 때는 **양쪽을 같이 잰다**: 정상이 안 걸리는가(오탐) **그리고**
진짜 위반이 여전히 걸리는가(변별력). 한쪽만 재면 통과하는 골든이 false assurance 가 된다.

## 7. 규칙이 계측과 다른 것을 말하면 지표가 거짓말을 한다

프롬프트가 "한 답변에 세 군데쯤"이라 하는데 검출기가 다른 단위를 세면, 모델이 규칙을 100% 지켜도
이벤트는 그대로 뜬다. **한쪽을 바꾸면 다른 쪽도 바꾼다** — 그 짝을 골든으로 묶는다
(`rule-detector-parity`). 주석으로 "같이 고쳐라"라고만 적으면 아무것도 강제하지 못한다
(그날 `telemetry-honesty` 가 정확히 그 상태였고, 고지와 실제가 어긋날 뻔했다).

## 8. 정규식으로 세기 전에 **실제 샘플을 눈으로 본다** (2026-08-16 · 하루에 아홉 번)

같은 날 계측이 아홉 번 틀렸다. 원인이 전부 하나다 — **대상을 안 보고 패턴부터 짰다.**

| 무엇을 재려 했나 | 왜 틀렸나 |
|---|---|
| en 페이지 한글 잔존 | 셸 `grep [가-힣]` 이 **바이트 매칭**이라 한자(甲·日干)까지 잡았다(47건 → 실제 2건) |
| glossary 훈 부착 | **BODIES 를 안 읽고** 항목 정의부만 봤다(정본은 "훈은 3단 본문에만"이라 적어 뒀다) |
| 같은 것 | `[가-힣]{2,}` 라 **한 글자 훈**("쓸 용(用)"·"것(신)")을 통째로 놓쳤다 |
| 대사 절 잇기 | 기준선을 **명령문**(PO 메시지)으로 잡았다(데이터 편향) |
| 쉼표 밀도 | 기준선을 **구어 전사**로 잡았다 — 거긴 쉼표가 0개다(표기 관습) |
| clean_tree 검증 | **이미 CRLF 인 파일**에 CRLF 변환을 또 걸어 `\r\r\n` 을 만들었다 |
| prune 검증 | "최근 백업이 남았나"를 봤는데 밀려나는 것은 *가장 오래된* 것이었다 |
| 복구 검증 | `savedCurrent` 만 보고 **복구 결과를 안 봤다** |
| 로그 리더 검사 | `/readServerLog/` 가 **import 줄**에 맞아 통과했다 |

★**규율**: 세기 전에 **매치 샘플 5~10개를 출력해 눈으로 읽는다.** 0 이나 100% 같은 극단이 나오면
  그건 발견이 아니라 **거의 항상 내 패턴이 틀렸다는 신호**다(오늘 "훈 부착 0%"가 그랬고,
  정본이 선례를 적어 뒀는데도 0 이 나왔다).

★**교차 확인 한 줄**: 정본·주석이 "이미 있다"고 말하는데 내 측정이 "없다"고 하면 **측정을 의심한다.**
  코드에 적힌 근거가 내 정규식보다 늙었을 뿐 틀린 경우는 드물다.

★**도구 선택**: 한글 검출은 셸이 아니라 node 로 한다. JS 정규식 `/[가-힣]/` 은 유니코드 범위라
  정확하고(한자 미검출 실측 확인), Git Bash 의 grep 은 그렇지 않다.

## 10. 파일을 고칠 때 어느 길로 가는가 (2026-08-16 · 세션 trace 실측)

내 도구 호출을 세어 봤다. 자기보고가 아니라 **기록**이다:

```
Edit 도구            267회 · 실패   3  (1%)
인라인 python 패치   664회 · 실패 113  (17%)
```

**전용 도구가 있는데 17배 잘 깨지는 길을 2.5배 더 자주 골랐다.**
실패 113건의 원인은 거의 하나다 — ①CRLF(파일은 `
`, 내가 쓴 패턴은 `
`)
②주변 공백·들여쓰기를 눈대중 ③이스케이프가 셸·heredoc 을 지나며 변함.

### 규율

1. **한 곳 치환 = `Edit` 도구.** 예외 없다. "여러 줄이라서"는 이유가 아니다(Edit 도 여러 줄 된다).
2. **여러 파일·여러 곳을 스크립트로 고칠 때만** `~/.claude/tools/patch.py` 를 쓴다.
   CRLF 보존·중복 일치 차단·원자성(하나 실패하면 아무것도 안 씀)·**못 찾으면 주변 표시**가 들어 있다.
   그 네 성질은 실제로 확인했다(실패 경로 포함).
3. **커밋 메시지는 heredoc 으로만.** `git commit -m "...\`...\`..."` 는 셸이 백틱을 실행한다
   — 오늘 실제로 파일명이 통째로 사라진 메시지를 커밋했다.

★이건 취향이 아니라 **측정된 실패율**이다. 다음에 인라인 패치를 쓰려 하면 이 표를 먼저 본다.

### ★2026-08-21 재측정 — 위 표의 "17배"는 **재현되지 않는다**(정직 정정)

위 수치는 **한 세션의 trace**에서 나온 것이다. 자가감사 스캔을 전수(프로젝트 디렉터리 8곳·1,137파일)로
고친 뒤 같은 것을 다시 쟀다. 도구 호출과 `is_error` 결과를 **tool_use_id 로 짝지어** 센 값이다:

```
Edit 도구      4,513회 · 실패 38 · 0.8%   ← 실패가 전부 그 도구 고유("String to replace not found")
Write 도구     1,389회 · 실패  8 · 0.6%
Bash 계열(인라인 패치·patch.py)            ← ★측정 불가로 판정
```

- **살아남는 결론**: `Edit` 는 표본을 17배 키워도(267 → 4,513) **실패율 1% 근처**다. 규칙의 방향은 옳다.
- **철회하는 것**: **"인라인이 17배 잘 깨진다"는 배수**. 세 판을 좁혀 봤지만 Bash 실패는
  ①사용자 거부 ②패치와 무관한 런타임 오류(DB·네트워크) ③분류 오탐(커밋 메시지에 `patch.py` 가 들어간 명령)
  이 섞여 **"그 경로가 깨졌다"만 분리해 낼 수가 없다.** 못 재는 것을 숫자로 말하지 않는다.
- ★**규칙은 그대로 둔다**(1·2번). 근거가 약해진 것은 배수 하나이고, 한 곳 치환에 `Edit` 를 쓰는 이유는
  실패율만이 아니다 — CRLF·주변 공백·이스케이프를 사람이 눈대중하지 않아도 되는 것이 본질이다.

★이 정정 자체가 교훈이다: **오래 신뢰해 온 수치일수록 먼저 의심한다.** 같은 날 자가감사 도구의
헤드라인 지표가 98% 잡음(1,241 → 26)이었고, 그 도구가 내 세션의 1/3 을 아예 안 읽고 있었다.

4. **bash heredoc 에 백슬래시·정규식이 든 문자열을 넣지 않는다**(2026-08-18 하루 3사고):
   (역슬래시 b) 가 리터럴 백스페이스로, `\d`/`\s` 가 반쪽으로 들어갔다 — 이 Windows bash 는 quoted
   heredoc 에서도 이스케이프를 한 겹 벗긴다. 코드/정규식 파일 생성은 **Write 도구**, 수정은 **Edit**.
5. **repo 를 넘나드는 세션에서는 경로를 절대경로로**(cwd 오발 2회: 남의 repo 에 테스트 생성·
   빈 커밋) — `cd A && ...` 체인 대신 파일 경로·`git -C` 를 쓴다.
6. ★**즉석 스크립트로 여러 파일을 고치지 않는다** (2026-08-21 · 같은 뿌리에서 하루 2사고).
   §10.2 가 이미 `patch.py` 를 쓰라고 하는데 나는 두 번 다 `io.open` 즉석 쓰기를 골랐고, 둘 다 다쳤다:
   - **줄바꿈 변조**: `.gitignore` 3개를 LF → **CRLF** 로 바꿔 한 줄 추가가 4줄 재작성 diff 가 됐다.
     하필 *빌드 산출물 잡음을 없애는 커밋*에서 잡음을 냈다(`patch.py` 는 CRLF 를 보존한다).
   - **중복 방지 표식이 주석에 매치**: 삽입 표식을 `"소스 합"`(문구)으로 뒀는데 직전에 넣은
     **주석 안의 "소스 합 8"** 에 걸려 2개 repo 에서 삽입이 조용히 건너뛰어졌다.
     그리고 이어 돌린 확인이 "정상"을 출력했다 — **코드가 없어서 안 뜬 것**이다(공허한 통과).
   ★규율 둘: ①여러 파일 스크립트 치환은 `patch.py`(CRLF 보존·못 찾으면 주변 표시·원자성).
   ②멱등 표식은 **코드 식별자로** 잡는다(주석 문구 금지 — §2 의 "검사는 주석이 아니라 코드를 본다"가
   내 패치 스크립트에도 그대로 적용된다). 삽입 뒤에는 `grep -c` 로 **실재를 확인하고** 다음으로 간다.

## 11. 검사가 대상보다 넓거나 좁으면 둘 다 거짓 안심이다 (2026-08-21)

같은 날 저장·복원 골든 하나를 쓰면서 **양쪽 방향으로 다 틀렸다.**

### 11.1 고치기 전에 **그 입력이 도달 가능한지** 확인한다 (넓은 쪽)

`rollToToday 가 부패 입력에도 죽지 않는다` 를 쓰자 RED 가 떴다. 결함으로 보였다.
고치기 전에 호출부를 읽으니 `page.tsx:396·416` 이 **이미 `store.today.date` 를 읽고 나서** 부른다
— `today` 가 없는 입력은 **도달 불가**였다.

거기에 방어를 넣었다면 ①죽은 코드 ②그 코드를 지키는 골든 ③"부패에 강하다"는 **거짓 안심**이 남는다.
★**RED 는 결함의 증거가 아니라 질문이다.** 먼저 물을 것: *이 입력이 실제로 그 함수에 도달하는가.*
호출부를 전수로 열거해 답한다(grep 으로 호출 지점 → 각 지점의 선행 조건).
도달 불가면 **검사를 실제 계약으로 바꾼다**(여기서는 "날짜가 바뀐 경우에만 초기화한다").

### 11.2 픽스처를 캐스트로 잠그면 **정본 드리프트가 숨는다** (좁은 쪽)

같은 파일에서 "유효한" 픽스처를 이렇게 썼다:

```ts
const src: Persisted = { habits: [{ id: "h1", text: "스트레칭" }], ... } as Persisted;  // ❌
```

정본은 `text` 가 아니라 `name`(+`kind`)이었다. **캐스트가 tsc 의 입을 막아** 검사는 초록으로 통과했다.
캐스트를 떼자 tsc 가 즉시 잡았다. ★**테스트도 정본을 안 읽으면 틀린다** — 그리고 틀린 채로 통과한다.

- **"유효하다"고 주장하는 픽스처에는 캐스트를 붙이지 않는다.** 타입 주석만 달고 tsc 에게 채점시킨다.
  가능하면 모듈의 **팩토리·생성자로 만든다**(`freshTally()` 처럼) — 정본이 바뀌면 같이 따라온다.
- **일부러 망가뜨린 입력에는 캐스트가 정당하다**(부패 방어·globalThis 스텁·경계 입력).
  실측 대조: 6 repo 36건 중 대다수가 이쪽이라 **캐스트 일괄 금지는 오탐 공장**이다.
  가르는 선은 캐스트의 유무가 아니라 **그 픽스처가 유효하다고 주장하는가**이다.

### 11.3 커버리지는 개수가 아니라 **아픈 경로**로 센다

6앱 테스트 수를 나란히 놓으면(434·89·12·10·7·5) 적은 쪽을 채우고 싶어진다. 그건 목표가 아니다.
물을 것은 하나다 — **깨지면 사용자가 무엇을 잃는가.** 저장·복원(=기록 손실)은 잠갔고,
저장 로직이 없는 앱은 **N/A 로 정직하게 닫았다**(억지 갭 금지).

## 12. 배선했다는 말은 **끝단에서 값을 본 뒤에만** 쓴다 (2026-08-21 · 하루에 다섯 번)

같은 날 "있지만 전달 안 됨"을 다섯 번 잡았고 **그중 셋은 내가 만든 것**이다.

| 무엇 | 배선은 있었다 | 그런데 |
|---|---|---|
| 판 위 표식 토큰 | `globals.css` 에 선언 존재 | 테마 블록 안이라 기본 테마에서 **빈 값** → 기물을 눌러도 갈 칸이 안 보였다 |
| 유료 후보 관심 | 버튼·이벤트·골든 7개 통과 | 요약은 **깊이가 늘 때만** 나가는데 관심 클릭은 깊이를 안 바꾼다 → 서버 도달 **0** |
| 유입 라벨 | `?src=` 를 읽어 이벤트에 넣음 | 요약·로그에 없어 **브라우저 밖으로 나간 적이 없었다**(판독기는 영원히 "미기록") |
| 계측 자체 | — | 한 앱은 아예 없었다(링크를 뿌려도 사람이 왔는지조차 모름) |
| 내 골든 | 배선의 *모양*을 검사 | **호출을 지워도 초록**이었다 |

★공통 원인은 하나다 — **끝단을 안 보고 "배선했다"고 말한 것.**

### 규율

1. **끝단에서 값을 본 뒤에만 완료라고 쓴다.** 계측이면 서버 로그에 그 줄이 찍힌 것을 눈으로 본다.
   화면이면 **계산된 스타일**을 잰다(선언이 있는 것과 그려지는 것은 다르다).
2. **골든은 모양이 아니라 도달을 본다.** 배선 검사에는 **소비처가 실제로 호출하는가**를 함께 넣는다
   (주석은 걷어내고 본다 — `// track(...)` 도 정규식에 맞는다).
3. **한 마디씩 잠근다.** 링크가 붙이는가 → 요약이 담는가 → 로그가 찍는가 → 판독기가 읽는가.
   한 마디만 검사하면 나머지가 끊겨도 전부 초록이다.
4. **확인용 호출에는 프로브 라벨을 붙인다.** 안 붙이면 내 확인이 실사용 집계에 섞인다
   (실제로 한 줄 섞었고, 지우지 않고 기록했다 — 로그를 고쳐 자기 흔적을 감추는 쪽이 더 나쁘다).

### 이식할 때 형태를 바꾸지 않는다

형제 앱에서 린트를 가져올 때 **그 앱의 구조에 맞는지 먼저 본다.** 등록 이벤트 전부가 판독기에
이름으로 나와야 한다는 검사를 그대로 옮겼더니 **13건이 걸렸는데 대부분 오탐**이었다 —
그 앱은 요약 한 줄만 서버로 보내고 나머지는 로컬 화면이 통째로 나열하는 구조였다.
**좁히거나 뺀다.** 넓은 검사는 소음이 되어 진짜 경보를 묻는다.

## 13. 문제를 만나면 **고치는 것으로 끝내지 않는다** (PO 상시 규칙 2026-08-21)

PO 원문: *"문제가 있을 경우 같은 문제가 생기지 않도록 해결부터"* · *"해결부터는 향후 문제 있을때마다 지속"*

즉 이건 한 번의 지시가 아니라 **상시 규율**이다. 문제를 만나면 순서가 정해져 있다:

1. **확증** — 측정으로 진짜 문제인지 먼저 가른다(오탐이면 여기서 끝난다).
2. **수리** — 그 인스턴스를 고친다.
3. ★**같은 클래스를 전수로 찾는다** — 한 곳에서 났으면 다른 곳에도 있다.
4. ★**재발을 기계로 막는다** — 린트·골든·훅. 메모리 노트는 재발을 못 막는다.
5. **좁힌다** — 오탐이 나오면 그 자리서 좁힌다. 소음이 된 검사는 진짜 경보를 묻는다.

### 실사례 (2026-08-21 · 이 규칙이 생긴 날)

투명도로 흐린 글자의 대비 미달:
- 확증: 라이브에서 재니 `opacity-40`=2.33:1 · `50`=3.02 · `60`=3.99 (하한 4.5) · `70`=5.40 통과
- 수리: 5앱 52곳을 **그 선만** 올렸다(70 이상은 이미 통과라 안 건드림 — 전부 손대면 churn)
- 전수: 같은 스윕으로 6호스트를 재서 44건 → 0건
- 기계화: `contrast-opacity-lint` 를 6앱 전부에 심었다
- ★**좁히기를 세 번 했다**(전부 반증·실측이 잡았다):
  ①`disabled:opacity-50` 을 결함으로 셈 → 비활성 면제(WCAG 1.4.3 이 inactive component 를 명시 면제)
  ②삼항식 `${capped ? "opacity-40" : ""}` 을 못 읽음 → 문맥 판정
  ③`disabled` 가 **앞 줄**에 있는 JSX 를 못 읽음 → 앞뒤 3줄 블록으로 확대

★**4번을 빼면 3번이 무의미하다.** 전수로 고쳐도 다음 사람(=다음 세션의 나)이 같은 손잡이를 다시 잡는다.
★**5번을 빼면 4번이 해롭다.** 오탐을 뿜는 린트는 결국 무시되고, 그러면 진짜가 지나간다.


## 14. 내 패턴은 거의 언제나 대상보다 좁다 (2026-08-21 · 하루에 아홉 종)

§8 이 "세기 전에 샘플을 보라"고 말하는데, 같은 날 그걸 아홉 번 어겼다. **전부 같은 뿌리**다 —
대상을 안 보고 패턴부터 짰고, **오탐과 위음성 양쪽으로** 틀렸다.

| 재려던 것 | 놓친 것 | 나온 헛 숫자 |
|---|---|---|
| hreflang 존재 | React 는 `hrefLang`(카멜케이스) | "홈 hreflang 0개" |
| 안전 경보 분모 | `chat_message` 이벤트는 없다(정본은 `usage_events`) | "분모 0" |
| 앱별 `e.message` | 상대 경로를 **다른 cwd** 에서 찾음 | "4앱 0건" |
| 도구 커버리지 | `[a-z]+\.도메인` 이 서브도메인 없는 주소를 못 잡음 | "한 앱 누락" |
| 고아 페이지 | 서버 HTML 만 봄(하이드레이션이 링크를 갈아친다) | "97% 고아" |
| 첫 화면 안내 | 문장 길이 상한 60자 | "4앱 모두 안내 없음" |
| 이벤트 조회 | `limit=N` 오름차순 = **가장 오래된** N줄 | "이탈 0건" |
| 도달성 골든 | ①`app/`만 스캔 ②템플릿 접두사만 ③보간 뒤 접미사 ④쿼리 ⑤부모=자식 가정 | 오탐 64군집·누락 48쪽 |
| 자가감사 교정 수 | 붙여넣기·형태소·중복 미구분 | 26(실제 11) |

### 규율

1. **극단값이 나오면 먼저 내 패턴을 의심한다.** 0·100%·"전부"는 신호가 아니라 대개 증상이다.
2. **판정식은 정본에서 파생한다.** 상수·이벤트명·경로를 손으로 다시 적는 자리가 다음 오탐이다.
3. ★**부분만 흉내 내지 않는다.** 템플릿 링크를 접두사로 흉내 내다 네 번 졌다 —
   통째로 정규식으로 바꾸자 끝났다. 흉내가 한 번 지면 다음 형태에도 진다.
4. ★**다 고쳐도 못 보는 것은 적는다.** 정적 검사로는 "사슬은 있는데 입구가 없는" 경우를 못 가린다.
   좁히는 대신 **한계를 주석에 남기고 진짜 판정을 라이브로 옮겼다**(`reachability.mjs`).

### 14.1 ★검사가 대상을 바꾸면 그건 검사가 아니다 (같은 날 최악형)

Stop 훅의 새 검사를 반증하려고 **훅을 직접 열여섯 번 돌렸다.** 그때마다 회차가 올라갔고,
상한에 닿자 훅이 **마커를 지웠다** — PO 가 지속을 지시한 루프가 내 검사 때문에 끊겼다.
반증 결과도 못 얻었다(마커가 없으면 훅은 조용히 끝난다). **손해만 남았다.**

→ 상태를 가진 것을 반증할 때는 **읽기 전용 모드를 먼저 만든다**(`LOOP_HOOK_DRY=1`).
   그리고 반증 안에서 **상태가 그대로인지도 함께 확인한다**.


## 15. 라이브 HTML 의 문자열은 렌더의 증거가 아니다 (2026-08-28 · 하루에 두 번)

같은 날 라이브를 재면서 두 번 같은 실수를 했다. **문자열이 있으면 그려진 줄 알았다.**

| 무엇을 재려 했나 | 내가 본 것 | 실제 |
|---|---|---|
| 광고 자리가 렌더되나 | 서버 HTML 에 `AdSlot` 이 있다 | RSC 페이로드의 **컴포넌트 이름**이었다. 실제 `<ins>` 는 0개(env 없어 휴면) |
| 언어 대체본이 걸렸나 | HTML 에 `hrefLang` 이 있다 | 역시 페이로드. 실제 `<link rel="alternate">` 를 세니 4개(정상) |

★원인은 하나다 — **React 서버 컴포넌트 페이로드에는 컴포넌트 이름과 props 가 문자열로 실린다.**
그래서 `grep AdSlot` 은 "그 컴포넌트가 존재한다"만 말하지 "그것이 무언가를 그렸다"를 말하지 않는다.

### 규율

1. **렌더를 재려면 태그를 센다.** `<ins`·`<link rel="alternate"`·`<h2` 처럼 브라우저가 실제로 만드는
   것을 세라. 컴포넌트 이름·props 키는 페이로드에도 있다.
2. **줄 수로 세지 않는다.** 프로덕션 HTML 은 한 줄이라 `grep -c` 가 항상 1 을 준다
   (같은 날 서버 렌더 갭 점검에서 이것도 걸렸다). `grep -o ... | wc -l` 로 **매치 수**를 센다.
3. **0 이나 "있음"이 나오면 반대 방향으로 한 번 확인한다.** 일부러 위반을 주입해 검사가 반응하는지
   보고 나서 숫자를 말한다(상표 스캔 0건을 그렇게 확증했다).
